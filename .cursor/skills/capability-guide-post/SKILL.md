# Capability guide post

Write a feature-education piece that moves readers from “chat toy” to real workflows. One product per piece. Prefer concrete actions over hype.

## Structure (do not skip)

1. **Hook** — one blunt line: most people only use ~10% of X.
2. **Promise** — for each capability: where it lives, how to turn it on, one ready-to-paste prompt.
3. **Parts** — group into clear sections, e.g. already-in-chat → role prompts → outside the chat (browser/files/schedules/skills) → builders → odd but useful.
4. **Close** — pick *one* capability to set up today; save the rest for later.

## Card template (repeat per capability)

- **Name** — short, concrete
- **Why it beats copy-paste chat** — one sentence
- **How to enable** — clicks/settings in plain words
- **Prompt block** — fenced, copy-ready, with `[placeholders]`
- **Guardrail** — when *not* to use it (one line)

## Writing rules

- Lead with the surprising angle; no corporate filler.
- Short paragraphs; numbers beat adjectives.
- No “revolutionary / disruptive / synergy”.
- Every prompt must be runnable as-is after filling brackets.
- Match the product’s real features; never invent toggles.
- If bilingual is required: English file + Chinese file with top `English | 中文` links (or the project’s existing i18n pattern).

## Output

Deliver the full draft in the requested language(s). End with a one-line checklist of capabilities covered.
